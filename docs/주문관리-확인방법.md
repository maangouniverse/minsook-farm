# 주문 상태와 알림톡 문구 확인 방법

실제 알림톡 발송은 꺼져 있습니다. 문구의 ‘사용’을 체크해도 이번 버전에서는 고객에게 발송되지 않습니다. 운송장 수정 시에도 재전송에 필요한 기록만 만듭니다.

## 직접 확인할 순서

실제 고객 주문 대신 확인용 주문을 사용해 주세요.

1. 관리자 주문 목록에서 주문자나 주문번호를 눌러 주문 상세를 엽니다. 아래 ‘진행사항’에서 변경 내용을 확인합니다.
2. 주문완료에서 입금완료로 바꾸고 저장합니다. 다시 열어 변경 전후 상태와 한국 기준 날짜·시간이 보이는지 확인합니다.
3. 택배발송으로 바꾸며 한진택배와 운송장 번호를 입력합니다. 번호가 없으면 저장을 막는지 확인합니다.
4. 주문 상세에서 운송장 번호를 수정합니다. ‘운송장 정보 변경 · 알림 재전송 준비’와 이전 번호·새 번호가 나와야 합니다. 택배사와 번호를 한 번에 바꿔도 알림 준비 기록은 한 건입니다.
5. 같은 내용을 다시 저장합니다. 이력과 알림이 더 생기지 않아야 합니다.
6. 주문취소로 바꿔도 기존 택배사와 운송장 번호가 남는지 확인합니다.
7. 상단 ‘알림톡 템플릿 관리’를 엽니다. 네 상태의 문구를 각각 저장하고 다시 열어 확인합니다.
8. ‘안내 문구’ 입력칸을 누른 다음 변수 버튼을 누릅니다. 선택한 위치에 변수가 들어가야 합니다. 변수는 발송 문구를 만들 때 실제 주문 정보로 바뀌는 자리입니다.
9. `#{픽업일시}`가 들어간 문구에서 ‘직접 픽업 주문’을 선택하고 미리보기를 누릅니다. 가상 픽업 날짜와 시간이 나와야 합니다. ‘택배 주문’을 선택하면 픽업일시가 없다는 안내가 나와야 합니다.
10. 택배발송 문구를 미리 봅니다. 운송장 번호와 배송조회 버튼, 번호가 포함된 한진 조회 주소가 나와야 합니다. 미리보기의 버튼은 외부 사이트를 열지 않는 확인용 표시입니다.
11. 같은 주문을 두 화면에서 열어 한쪽을 먼저 저장합니다. 다른 쪽에서 저장하면 변경 내용을 다시 확인하라는 안내가 나와야 합니다.
12. 휴대전화에서도 문구 입력, 저장, 주문 상세의 진행사항 확인이 가능한지 확인합니다.

기존 주문에는 과거 시각을 임의로 넣지 않습니다. ‘이력 관리 도입 전 주문’이라고 표시하고 이번 기능 적용 후의 변경부터 기록합니다. 관리자별 계정 구분이 없는 현재 로그인 방식에서는 처리 주체를 ‘관리자’로 표시합니다.

## 알림 안내 문구의 의미

- **템플릿 사용 안 함**: 해당 상태의 문구를 사용하지 않도록 설정했습니다.
- **정보 없음 / 설정 필요**: 문구에 필요한 주문 정보 또는 다른 택배사의 조회 링크 설정이 없습니다.
- **승인 템플릿 코드 없음**: 비즈톡에서 승인받은 템플릿의 식별 코드를 입력해야 합니다.
- **실제 발송 꺼짐**: 준비 내용을 저장했지만 고객에게 보내지는 않았습니다.

문구 저장은 비즈톡 승인 신청이 아닙니다. 처음 제공되는 안내 문구도 미승인 예시이며, 네 상태 모두 ‘사용 안 함’으로 시작합니다. 택배발송 문구에는 운송장 번호 변수와 배송조회 버튼이 필요합니다.

## 실제 발송을 연결할 때

비즈톡 연동 안내서, 발신 채널 정보, 승인받은 문구·변수·버튼 정보를 확인한 뒤 발송 연결을 별도로 구현해야 합니다. 비밀번호나 인증키는 문구 입력칸에 넣지 마세요. 과거 미발송 기록은 나중에 자동 발송하지 않습니다.

실제 알림톡 수신 확인은 사람이 직접 진행합니다. 이번 작업에서는 실제 발송 서비스를 한 번도 호출하지 않았습니다.

## 개발 확인 기록

가상 주문과 별도 SQLite 저장소에서 다음을 확인했습니다: 신규 접수와 변경 이력, 중복 접수 방지, 운송장 수정 시 알림 한 건 추가, 동시 수정 충돌, 저장 실패 시 주문·이력 함께 되돌리기, 배송정보 보존, 변수·픽업일시·한진 링크, 관리자 로그인 필요 여부, 템플릿 저장과 재조회.

기존 주문 접수, 계좌 복사, 가격 계산, 배송 엑셀 검사도 실행했습니다. 실제 운영 저장소(PostgreSQL)에 연결하거나 운영 사이트에 배포하지 않았습니다. 운영 반영 시에는 기존 데이터 백업 후 별도 PostgreSQL 시험 환경에서 저장과 동시 수정 동작을 추가 확인해야 합니다.
