# 주문접수 알림톡 준비 상태

실제 발송은 비활성화되어 있습니다. API 규격과 승인 템플릿이 제공되지 않아 외부 발송 코드는 연결하지 않았습니다. 환경변수만 바꿔도 발송되지 않습니다.

현재 준비된 부분:

- 주문 저장 후에만 별도 처리 기록을 만듭니다. 기록 저장 오류가 있어도 접수된 주문은 유지합니다.
- 같은 접수 키와 같은 내용은 기존 주문번호를 반환합니다. 같은 키로 내용이 달라지면 충돌로 처리합니다.
- 주문별 알림 기록은 한 건이며 자동 재발송하지 않습니다. 발송하지 않은 과거 주문을 나중에 일괄 발송하지 않습니다.
- 관리자 상단 ‘알림톡 상태·기록’에서 미발송 사유와 처리 상태를 확인합니다.
- 로컬 자동검사에서만 가짜 발송 함수를 주입합니다. 실제 비즈톡이나 고객 번호로 연결하지 않습니다.

## 준비해 주실 자료

1. 비즈톡에서 해당 계정에 제공한 API 연동 가이드: 서비스명·버전, 인증 방식, 요청 및 응답 규격, 결과 조회/콜백, 중복 요청 처리 규칙.
2. 연동 가능한 비즈톡 계정과 발송 권한·잔액 확인. 인증 비밀값은 채팅이나 저장소에 넣지 말고 운영 서버의 환경변수에 등록합니다. 정확한 환경변수 목록은 실제 인증 규격을 확인한 뒤 정합니다.
3. 민숙농장 카카오 비즈니스 채널과 발신 프로필 식별값, 알림톡 발송 승인 여부.
4. 승인된 템플릿 코드, 전체 문구, 변수 이름, 버튼 종류·문구·URL. 무통장입금과 현장결제 안내를 구분할 수 있는 승인 템플릿이 필요합니다.
5. 본인이 수신 확인할 테스트 번호. 다른 고객에게는 테스트하지 않습니다.

템플릿에는 주문번호, 주문상품·수량·단위, 최종 결제금액, 택배/픽업 구분, 주문 확인 안내가 필요합니다. 무통장입금에는 기존 입금계좌와 최종 입금금액을 넣고, 현장결제에는 입금 안내를 넣지 않습니다. 실제 승인 문구와 변수를 받은 뒤 정확히 대응시킵니다. 주문접수는 입금확인이나 결제완료가 아닙니다.

## 후속 연결 및 검증

- 현재 `BIZTALK_MODE` 기본값은 `off`입니다. 실제 서버는 전송 함수를 연결하지 않습니다.
- 자료 수령 후 서버 전용 모듈에 인증·승인 템플릿 매핑과 발송 결과 조회를 구현합니다. 클라이언트에는 인증값을 내려주지 않습니다.
- `BIZTALK_MODE=test`와 `BIZTALK_TEST_PHONE`의 지정 수신번호 제한을 유지한 채 사용자 번호로만 시험합니다. 템플릿 내용과 수신 결과를 사용자가 확인한 뒤 운영 발송을 별도로 활성화합니다.
- 요청 접수(`accepted`)와 실제 수신 성공(`delivered`)은 구분합니다. 통신 결과가 불명확하면 `unknown`으로 남기고 자동 재시도하지 않습니다. 프로세스가 중단되어 `processing`에 남은 주문도 비즈톡 결과를 먼저 대조해야 합니다.
- 실제 규격 확인 후 제공사 오류코드를 안전한 오류 분류에 대응시켜 관리자가 실패 원인을 구분하도록 보완합니다. 비밀값·원문 응답·고객 개인정보는 오류 기록에 남기지 않습니다.
- 상세주소 없음/있음, 할인·배송비 유지, 중복 접수, 발송 오류 시 주문 보존을 로컬 DB로 검증합니다. 가짜 전송 함수 검사는 실제 알림톡 발송 검증으로 보고하지 않습니다.

스키마는 기존 주문을 삭제하거나 수정하지 않고 접수키 필드 2개와 고유 인덱스, 알림 처리 기록 테이블을 추가합니다. 기존 주문의 키는 비워 둡니다. 운영 점검 시 실제 고객 주문을 테스트로 변경하거나 삭제하지 않습니다.
