# 알림톡 연동 준비 상태

실제 발송은 비활성화되어 있습니다. 서버는 외부 발송 함수를 연결하지 않습니다. 환경변수나 템플릿의 사용 여부만 바꾸어도 발송되지 않습니다.

현재 구현된 기능:

- 주문 생성, 상태 변경, 택배사·운송장 번호 변경을 기록합니다.
- 주문 저장과 변경 이력, 이벤트별 알림 준비 기록은 같은 트랜잭션으로 저장합니다. 어느 하나라도 저장에 실패하면 함께 되돌립니다.
- 같은 접수 키로 들어온 같은 주문은 기존 주문번호를 반환합니다. 변경 요청에는 주문 버전(revision)이 필요하며, 오래된 화면의 수정은 409 응답으로 거부합니다.
- 운송장 정보 변경 시 택배발송 템플릿으로 재전송 준비 기록을 생성합니다. 상태와 배송정보를 한 번에 바꾸어도 알림 준비는 한 건입니다.
- 관리자 상단 ‘알림톡 템플릿 관리’에서 상태별 문구, 변수, 승인 코드와 버튼을 설정합니다. 새 템플릿은 모두 사용 안 함입니다.
- 미리보기는 서버가 만든 가상 주문만 사용하며 외부 서비스를 호출하지 않습니다.
- 기존 주문당 알림 기록은 보존합니다. 새 기록은 변경 이벤트별로 쌓이며 ‘알림톡 상태·기록’과 주문 상세에서 미발송 사유를 확인합니다.
- 비활성 기간의 알림을 나중에 일괄 발송하거나 자동 재시도하지 않습니다.

## 후속 연동에 필요한 자료

1. 해당 비즈톡 계정의 API 안내서: 서비스명·버전, 인증 방식, 요청·응답, 결과 조회·콜백, 중복 요청 처리 규칙.
2. 계정의 발송 권한과 잔액 확인. 인증 비밀값은 대화나 저장소에 넣지 말고 운영 서버 환경변수에 등록합니다.
3. 민숙농장 카카오 비즈니스 채널과 발신 프로필 식별값.
4. 승인된 템플릿 코드, 전체 문구, 변수, 버튼 종류·문구·URL. 무통장입금과 직접 픽업 현장결제를 고려해야 합니다.
5. 사람이 직접 수신 확인할 테스트 번호.

실제 연결 후에도 제공사의 요청 접수와 고객 수신 성공을 구분해야 합니다. 결과가 불명확할 때는 자동 재전송하지 않고 제공사 결과를 먼저 확인해야 합니다. 기존 미발송 준비 기록을 실제 발송 대기열로 변환하지 않습니다.

사용자 확인 절차는 [주문관리-확인방법.md](주문관리-확인방법.md)에 있습니다. AI 개발·검증 중 실제 비즈톡 발송 호출은 금지하며, 실제 수신 시험은 후속 연동 후 사람이 직접 수행합니다.
