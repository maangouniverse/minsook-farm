# 민숙농장 솔라피 알림톡 연결

현재 솔라피 가입과 카카오 비즈니스 채널 준비가 되어 있습니다. 채널 연결, 템플릿 승인, 서버 설정, 실제 수신 확인이 남아 있습니다. 코드 기본값은 발송 꺼짐입니다.

## 연결 순서

1. 솔라피에서 민숙농장 카카오 비즈니스 채널을 연결합니다. 채널 관리자 인증은 계정 관리자가 진행합니다.
2. 아래 세 문구를 알림톡 템플릿으로 등록하고 검수를 요청합니다. 등록용 이름은 각각 `민숙농장_주문완료`, `민숙농장_입금확인`, `민숙농장_택배발송`으로 제안합니다. 일곱 가지 관리 상태는 이 세 알림 시점으로 묶어 사용합니다. 이름과 솔라피가 발급하는 템플릿 ID는 다릅니다.
3. 승인 후 주문페이지 관리자 → 알림톡 템플릿 관리에서 해당 상태의 템플릿 ID·본문·변수·버튼을 승인본 그대로 저장하고 ‘사용’을 체크합니다. 솔라피는 승인된 템플릿을 기준으로 발송하므로 로컬 미리보기만 수정해서는 실제 문구가 바뀌지 않습니다.
4. API 키와 API Secret은 운영 서버의 환경변수에 등록합니다. 채팅·소스 코드·관리자 화면에 넣지 않습니다.
5. `SOLAPI_MODE=test`와 지정 테스트 번호로 세 알림을 실제 확인합니다. 이 모드는 모의 발송이 아니라 지정 번호에 실제 발송하는 모드입니다.
6. 수신과 문구 확인 후 `SOLAPI_MODE=live`로 전환하고 재배포합니다. 발송 전에 솔라피 잔액과 계정 발송 권한도 확인합니다.

카카오 검수 일정은 보장할 수 없습니다. 솔라피는 통상 영업일 1~3일로 안내합니다.

## 템플릿 등록 초안

아래는 검수 신청용 초안이며 승인된 문구가 아닙니다. 결제 방식이 다른 직접 픽업 주문에도 잘못된 입금 요청을 보내지 않도록 주문완료 알림에는 입금 요구를 넣지 않았습니다. 계좌 안내는 기존 주문완료 화면에서 유지합니다.

### 주문완료 — 관리자 상태 ‘주문완료’

```text
[민숙농장 주문완료]
#{주문자명}님, 주문이 접수되었습니다.

주문번호: #{주문번호}
주문금액: #{주문금액}

주문해 주셔서 감사합니다.
```

버튼 없음.

### 입금확인 — 관리자 상태 ‘입금확인’

```text
[민숙농장 입금확인]
#{주문자명}님, 주문하신 상품의 입금을 확인했습니다.

주문번호: #{주문번호}
주문금액: #{주문금액}
```

버튼 없음. 실제 입금을 확인한 뒤 관리자가 결제 상태로 변경할 때 발송합니다. 은행 거래내역 자동 조회 기능은 포함하지 않습니다. 현장결제 픽업 주문은 이 입금 문구를 보내지 않도록 별도 차단합니다.

### 택배발송 — 관리자 상태 ‘택배발송’

```text
[민숙농장 택배발송]
#{주문자명}님, 주문하신 상품을 발송했습니다.

주문번호: #{주문번호}
택배사: #{택배사}
운송장번호: #{운송장번호}

아래 버튼에서 배송 상황을 확인하실 수 있습니다.
```

웹링크 버튼 이름: `배송조회`

모바일·PC 링크: `https://www.hanjin.com/kor/CMS/DeliveryMgr/WaybillResult.do?mCode=MN038&schLang=KR&wblnum=#{운송장번호}`

솔라피에 위 링크를 등록했다면 주문페이지 관리자에도 같은 링크를 입력합니다. 현재 배송조회 링크 자동 생성은 한진택배 기준입니다. 다른 택배사를 사용한다면 해당 택배사의 올바른 조회 링크를 별도로 설정해야 합니다.

## 서버 환경변수

| 이름 | 설정 |
| --- | --- |
| SOLAPI_MODE | off / test / live, 기본 off |
| SOLAPI_API_KEY | 솔라피 API Key |
| SOLAPI_API_SECRET | 솔라피 API Secret |
| SOLAPI_PF_ID | 연결된 민숙농장 카카오 채널의 pfId |
| SOLAPI_TEST_PHONE | test 모드에서 실제 수신할 휴대전화 번호 |

문자 대체 발송은 꺼져 있습니다. 알림톡 실패를 SMS로 자동 전환하지 않습니다. 테스트 번호와 일치하지 않는 주문은 테스트 모드에서 발송을 차단합니다.

## 동작과 확인

- 주문 접수와 알림 기록을 먼저 함께 저장하고, 저장 성공 후 솔라피를 호출합니다.
- 같은 주문 접수 요청을 다시 보내도 주문완료 알림을 중복 발송하지 않습니다. 택배·픽업·결제방식에 따른 접수 상태끼리 바꿔도 주문접수 알림을 다시 보내지 않습니다.
- 택배발송 상태의 운송장 수정은 수정된 정보로 새 배송 알림을 만듭니다. 발송 전 운송장 입력만으로 배송 알림을 보내지 않습니다.
- 주문취소를 포함한 주문상태 7개 모두 승인 템플릿 ID와 사용 설정이 있으면 발송합니다.
- 관리자 ‘알림톡 상태·기록’에서 요청 접수, 수신 성공, 발송 실패, 결과 미확인을 구분합니다. ‘솔라피 수신 결과 확인’은 결과 조회만 하며 재발송하지 않습니다.
- 발송이 꺼져 있던 기간의 주문은 나중에 자동 발송하지 않습니다.
- 요청 중 통신이 끊기거나 서버가 종료되면 결과 미확인 또는 결과 확인 필요로 남을 수 있습니다. 솔라피 발송 내역에서 주문 이벤트 식별값을 대조한 뒤 처리합니다. 자동 재전송하지 않습니다.
- 주문 저장 직후 서버가 종료되면 처리 대기 기록이 남을 수 있습니다. 현재 별도 주기 작업은 없으므로 관리자 기록과 솔라피 내역을 확인해야 합니다.
